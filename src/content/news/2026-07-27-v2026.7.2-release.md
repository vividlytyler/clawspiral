OpenClaw 2026.7.2 has landed as a pre-release, packed with a broad set of improvements that span remote workflows, mobile automation, desktop UI, and backend reliability.

**Remote coding sessions** are the marquee feature: operators can run Control UI sessions on cloud workers, open Codex and Claude catalog sessions in a terminal on their owning hosts, and resume OpenCode and Pi sessions directly from a terminal. Control UI catalog terminals can open eligible Codex and Claude Code sessions in the native CLI with an interactive PTY relay.

**Native automation and nodes** reach new parity: automations come to mobile, foreground Voice Wake lands on Android, and camera, location, and notification capabilities are now exposed from headless Linux nodes.

**Channel security** gets important fixes: Telegram durable-ingress loss after restarts is prevented, Signal stop and approval controls stay responsive during active turns, and channel allowlists no longer incorrectly grant owner access.

**Linux packaging** makes its debut: Linux deb and AppImage bundles ship with Gateway guidance, published from stable main-based releases. Windows installs also continue immediately after winget adds Node.js.

**External gateway supervision** is a new operational mode: `OPENCLAW_SUPERVISION_MODE=external` lets lifecycle owners (including enterprise tools like OCM) preserve verified restart and deferral behavior without exposing native service authority.

**Guided Control UI setup** now includes a settings page for model providers, a guided onboarding flow for channels, and image/model selection at session creation.

**Skill Workshop** now runs agent-initiated apply, reject, and quarantine actions without an additional approval prompt by default, while preserving `skills.workshop.approvalPolicy: "pending"` as an opt-in gate.

**Model defaults** shift to GPT-5.6: fresh API-key setups now default to `openai/gpt-5.6` (Sol alias), with Sol set to medium reasoning across both runtimes.

**iOS offline chat** joins the platform: recent sessions and transcripts are pre-painted from a protected per-gateway cache, with cached conversation text purged on pairing reset.
